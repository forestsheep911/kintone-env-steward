# 管理页派生采集流程

当官方 MCP 或公开 REST API 无法覆盖环境级目录、容量或系统级设置时，使用管理页派生的只读适配器补充证据。它们不是公开 API 契约，必须在快照中标记为 `ui-derived`，记录页面/资源版本、采集时间、响应结构与覆盖缺口。

## 三层快照

1. **管理目录层**：`/k/admin/app/` 的 CSV 清单发现全部管理可见 App，含已启用、有更改和未启用状态。不要用 MCP 的 App 清单替代此层。
2. **已发布配置层**：官方 MCP/REST 读取已发布或有未发布修改的 App 的字段、布局、流程、一般设置与部署状态。
3. **按需预览层**：仅对管理目录已发现、且被明确选中的未启用 App ID，调用 `preview` REST 端点读取测试环境 schema。不得猜测或枚举 ID 范围。

## 系统级补充

- `/k/admin/system/`：空间容量、来宾计数、全局 JS/CSS 摘要、插件、功能开关、移动端、共享 App 权限控制、系统监控。
- `/admin/`：磁盘与服务许可、共通管理员数量、审计配置、登录安全、集成摘要、区域设置、系统邮件和更新选项。

当前采集器已实现全量 App CSV、App 容量、`/admin/` 首页的磁盘/许可摘要，以及
审计设置、登录安全、OAuth 摘要、组织访问控制和管理员人数。`/k/admin/system/` 的
系统 JavaScript/CSS 摘要（启用、可执行、范围、文件数）也已实现；其余子菜单与
插件摘要（市场/导入数量、已安装数量、关联 App 总数）也已实现；其余子菜单与 API
Token 列表仍必须标记为部分覆盖，直至专用解析器完成。空间与来宾已采集许可上限、
使用量、来宾总数和来宾两步验证状态，不含空间或来宾明细。
共享 App 设置已采集针对 Everyone 组的应用管理和记录导出限制开关。
系统监控已采集全文搜索最旧任务的延迟秒数。
移动端显示模式已采集默认模式和是否允许用户自行选择。
功能启用页仅采集启用功能键名以及启用/禁用数量，不采集邮件格式等非治理摘要设置。
低优先级补充：页眉仅采集 KDS 外观启用状态；更新选项仅采集通道、默认策略和各类选项计数。

未覆盖的管理页（例如 API Token 列表、恢复、用户使用情况、性能页、AI、Web 表单及外部连接器）
保持为明确 coverage gap，不进行高成本抓取或保存明细。

只保存治理所需的摘要、计数、状态与非敏感元数据。不得保存用户名、邮箱、来宾明细、Cookie、Token、密码、证书、脚本正文、外部连接完整配置或记录内容。

## 运行规则

- 只允许经过审查的 GET 或命名为 `initialData`、`list`、`get`、`count` 的只读适配器；每个新端点先做结构探测并验证不会触发更新。
- 永不调用或模拟点击 `add`、`update`、`save`、`delete`、`enable`、`disable`、`deploy`、`restore`、`import`、`export`、`manual refresh` 等动作。
- `403`、空结果、未知字段和页面不可用都应写入 coverage/unknowns，不能视为“未配置”。
- 未启用 App 仅在同时无字段、无记录、无 Token、无自定义且无依赖时，才可列为待确认清理候选；绝不自动删除。
