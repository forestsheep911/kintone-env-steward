# 产品范围与治理模型

## 治理对象

| 领域 | 首批对象 | 典型问题 |
| --- | --- | --- |
| 资产 | 环境、空间、App、负责人、用途 | 无负责人、用途不明、重复或废弃 App |
| Schema | 字段、字段代码、类型、布局、视图 | 命名漂移、重复字段、关键设计不一致 |
| 流程 | 状态、动作、执行人 | 无终态、责任不清、流程与实际作业脱节 |
| 权限 | App、记录、字段权限 | 权限过宽、规则冲突、旧组织残留 |
| 身份 | 用户、组织、组、服务账号、管理员 | 离职账号、孤儿账号、组用途不明、管理员过度集中 |
| 扩展 | JS/CSS、插件、Webhook、集成 | 无所有者、来源不明、环境差异 |
| 生命周期 | 创建、变更、例外、废弃 | 无变更记录、例外过期、长期未复核 |
| 数据健康信号 | 记录量、更新时间、空值率等聚合值 | 佐证 schema 风险 |

## 治理单元

每条治理发现至少包含：

- `rule_id`：稳定的规则标识；
- `subject`：环境、空间、App、用户、组织、组或具体配置对象；
- `observation`：直接观察到的事实；
- `evidence`：来源、采集时间和原始定位；
- `assessment`：为什么可能构成风险；
- `severity`：影响等级；
- `confidence`：证据完整度；
- `recommendation`：建议动作；
- `exception`：已批准例外及到期时间；
- `verification`：如何确认整改完成。

## 操作等级

- **Level 0：离线设计。** 只处理用户提供的文档、导出和样例。
- **Level 1：只读发现。** 读取元数据和配置，生成快照与报告；默认等级。
- **Level 2：整改计划。** 生成精确 diff、依赖、风险和验证步骤，不执行。
- **Level 3：受控变更。** 仅执行明确支持且当次确认的变更；`0.0.x` 不实现。

## 与数据分析的边界

环境治理可以使用记录级统计作为辅助信号，例如长期无更新、实际空值率或流程状态
堆积。默认只取聚合值，不保存业务记录内容。销售漏斗、续约风险和经营指标属于业务
分析产品，应通过独立模块或下游项目完成。
